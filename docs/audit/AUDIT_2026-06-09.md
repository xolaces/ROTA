## Wave 0c batch 1 — FIXED + TESTED (verified by a dedicated read-only agent, then implemented)

1. **Gem-spend balance race (high, 2 lenses)** — was self-documented ("double-spend possible…Phase 2").
   `IGemTransactionRepository.TrySpendAsync`: idempotency + balance + −amount insert under a per-player
   `pg_advisory_xact_lock` in one tx (ambient-tx aware). GemService delegates; audit on Charged only.
2. **Gem ledger unique-violation catch (medium)** — `TryCreateAsync` absorbs 23505 into a clean
   "already granted" false; GrantGemsAsync uses it (concurrent duplicate grant no longer 500s).
3. **Fractional regen destroyed on every checkpoint (high)** — CONFIRMED (a 4-min remainder under a
   5-min/point rate died on every spend). Fix: `ComputeLiveValueWithCarry` backdates the checkpoint by
   the remainder (zero schema change); at/above cap the clock restarts (no banking). Spend/Refill/Drain
   all carry; 2 regression tests (carry preserved off-cap, no banking at cap).
4. **Seeded pools vs ComputeMax mismatch (high)** — CONFIRMED (first Energy allocation clamped 25→11,
   destroying 14 max + 14 current; first Stamina allocation jumped 5→11). **OWNER DECISION: keep the
   25/5 playtested feel** — formula rebased to `PlayerStats.BaseMaxEnergy(25)/BaseMaxStamina(5) +
   investment`; Player.CreateWithId seeds now reference the constants (can never drift again);
   CLAUDE.md design-decision section amended.
5. **(scoped as next-wave ticket — OWNER DECISION)** players-row optimistic concurrency: simultaneous
   quest+raid rewards last-write-wins (lost XP/gold; level-up refill can double-fire, gems already
   idempotent). Fix = Postgres `xmin` concurrency token + retry on QuestService/RaidService player
   writes, with concurrency integration tests. First ticket of the next backend wave (T59).

## Wave 0b — FIXED + TESTED (the 6 adversarially-confirmed findings)

All six are now implemented and green. Summary of fixes:
1. **Refresh rotation** — atomic conditional UPDATE latch (`IRefreshTokenRepository.TryRevokeAsync`); replay of a rotated token OR a lost rotation race → `RevokeAllActiveAsync` (breach detection / `TokenReplayDetected` audit).
2. **Global ban gate** — new `BanGateMiddleware` (after auth + audit) 403s any mutating request from an `IsBanned` player. **Follow-up: no dedicated HTTP-pipeline integration test yet** (the suite resolves services directly and never exercises middleware — building the first HTTP-level harness is its own ticket).
3. **Session cap** — `IssueTokenPairAsync` now trims to the cap in a loop (`while count >= Max`), so drift can't leave it permanently exceeded.
4. **Rate-limit DoS** — middleware moved AFTER `UseAuthentication`; per-player bucket keys on the VERIFIED principal; unauthenticated game-route traffic falls back to a per-IP bucket.
5. **Last-admin TOCTOU** — `IPlayerRepository.TryDemoteAdminAsync` does count+clear under a fixed advisory lock so concurrent demotions serialize.
6. **Raid-chat IDOR** — `ChatHub.JoinRaid`/`SendRaidMessage` now participant-gated (parse GUID → `FindByRaidAndPlayerAsync`); group key canonicalized.
